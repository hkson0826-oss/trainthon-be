# Lumina 주차장 사고 증거 매칭 — 데모 MVP Scope

작성일: 2026-09-09  
데모 기준 기기: **iPhone 11, 세로 화면(375×812pt 기준)**

## 1. 데모 목표

이번 MVP의 핵심 장면은 **Y가 올린 약 20초의 Mock 블랙박스 영상에서 실제 AI가 사고 후보 순간을 찾아 X의 사고 요청과 연결하는 것**이다.

> **TwelveLabs 무료 플랜 + X의 피해 차량 사진 + Y의 약 20초 Mock 블랙박스 영상** 조합으로 구현한다.

## 2. 데모 한 줄 흐름

> X가 A주차장 사고와 피해 차량 사진을 등록한다 → 해당 시간대의 데모 방문 기록을 가진 Y에게 인앱 알림이 생성된다 → Y가 약 20초의 블랙박스 영상을 올린다 → TwelveLabs가 실제 영상을 분석한다 → 사고 후보 타임스탬프를 누르면 해당 장면이 재생된다 → 보험사 채택과 Y 보상 예정 상태를 데모로 보여준다.

## 3. 구현 범위

| 기능 | 구현 방식 | 실제/Mock |
|---|---|---|
| X 사고 제보 | 장소, 사고 시간, 피해 차량 정보, 설명을 입력하고 서버에 저장 | 실제 |
| X 자료 업로드 | 피해 차량 사진 1~2장 업로드 | 실제 |
| Y 방문 이력 | `A주차장 13:58~14:12` 기록을 미리 저장 | Mock |
| Y 알림 | X의 장소·시간과 Y의 방문 기록이 겹치면 인앱 알림 생성 | 실제 로직 + Mock 이력 |
| Y 영상 업로드 | 검증된 약 20초 Mock 블랙박스 MP4 한 개 업로드 | Mock 영상, 실제 업로드 |
| AI 영상 분석 | TwelveLabs Analyze API 호출 | 실제 |
| 분석 결과 | 사고 후보 여부, 타임스탬프, 차량 특징, 관찰 내용, 일치 근거 표시 | 실제 AI 응답 |
| 보험사 채택 | 발표자가 버튼으로 `검토 중 → 채택` 상태 변경 | Mock |
| 에스크로 | `예치 완료 → 보상 지급 예정` 상태 변경 | Mock |

## 4. X 사용자 흐름

1. X가 `사고 제보하기`를 누른다.
2. 사고 장소를 `A주차장`으로 선택한다.
3. 사고 추정 시간을 `14:00~14:10`으로 입력한다.
4. 피해 차량 색상·차종·파손 부위를 입력한다.
5. 피해 차량 사진 1~2장을 업로드한다.
6. 제보를 등록하면 Y 방문 기록과 장소·시간을 비교한다.

X는 영상을 업로드하지 않는다. 피해 차량 사진과 텍스트 정보만 사용한다.

## 5. Y 사용자 흐름

1. Y 계정에는 `A주차장 13:58~14:12` 방문 이력이 미리 저장되어 있다.
2. X의 제보가 등록되면 Y에게 인앱 알림이 나타난다.
3. Y가 알림을 열어 사고 장소와 요청 시간대를 확인한다.
4. Y가 SD카드에서 가져온 것으로 가정한 약 20초의 Mock MP4를 선택한다.
5. 업로드 진행률을 확인하고 `AI 분석 시작`을 누른다.
6. 분석이 끝나면 사고 후보 타임스탬프와 결과를 확인한다.

## 6. TwelveLabs 실제 분석

백엔드가 영상을 TwelveLabs Analyze API로 보내며, 브라우저에서 API 키나 공급자 API를 직접 호출하지 않는다.

분석 프롬프트에는 다음 X 정보를 포함한다.

- 사고 장소와 시간대
- 피해 차량 색상과 차종
- 파손 부위
- 사고 설명
- 지원되는 경우 피해 차량 참고 사진

최소 결과 형태:

```json
{
  "incidentDetected": true,
  "incidentTimestampSeconds": 12,
  "victimVehicle": "흰색 세단",
  "otherVehicle": "검은색 SUV",
  "event": "검은색 SUV가 후진하며 흰색 세단 우측 후면에 접촉한 것으로 보이는 장면",
  "relevance": "HIGH",
  "evidence": [
    "피해 차량의 색상과 차종이 사고 요청과 일치",
    "신고된 파손 부위와 접근 방향이 유사"
  ]
}
```

AI 결과는 가해 차량, 사고 사실 또는 과실을 확정하지 않는다. 번호판 정확 인식도 MVP 완료 조건에 포함하지 않는다.

## 7. iPhone 11 FE 데모 화면

모든 핵심 흐름은 iPhone 11 세로 화면 하나에서 끊김 없이 시연할 수 있어야 한다.

### 필수 화면

1. X 사고 제보 폼
2. X 제보 완료 및 사고 접수 완료화면
3. Y 인앱 알림 목록
4. Y 사고 요청 상세
5. Y 영상 선택·미리보기·업로드 화면
6. AI 분석 진행 화면
7. 영상 플레이어와 사고 후보 타임스탬프 결과 화면
8. X에게 사고 후보 영상 발견 알림 화면
9. 보험사 채택· Y 보상 예정 화면

### 모바일 UI 제약

- 기준 viewport는 `375×812`로 잡고 320px 너비까지 가로 스크롤 없이 동작하게 한다.
- 모든 주요 버튼의 터치 영역은 최소 44×44pt로 한다.
- 하단 고정 버튼은 iPhone Safe Area를 침범하지 않게 `env(safe-area-inset-bottom)`을 반영한다.
- 파일 선택은 iOS Safari의 사진 보관함·파일 앱 선택 흐름을 사용한다.
- 영상은 MP4 한 개만 받고 선택 직후 모바일 화면 안에서 미리보기를 제공한다.
- 영상 플레이어는 16:9 전체 너비로 표시하고, 분석 카드가 플레이어 아래에 한 열로 이어지게 한다.
- 타임스탬프 버튼을 누르면 플레이어의 `currentTime`을 변경하고 바로 재생한다.
- 분석 중에는 화면을 막는 긴 스피너 대신 `업로드 완료 → AI 분석 중 → 결과 정리 중` 단계를 보여준다.
- X/Y 계정 전환은 데모용 상단 스위치 또는 프로필 메뉴로 빠르게 수행한다.

## 8. 발표용 데모 시나리오

1. iPhone 11에서 X 계정으로 사고 요청과 피해 차량 사진을 등록한다.
2. 완료 화면에서 `같은 시간대 방문 사용자 1명 발견`을 보여준다.
3. Y 계정으로 전환해 새 알림을 확인한다.
4. 약 20초의 Mock 블랙박스 영상을 선택하고 업로드한다.
5. 실제 TwelveLabs 분석 진행 상태를 보여준다.
6. 결과에서 `00:12 사고 후보`를 누른다.
7. 영상이 12초 지점으로 이동해 사고 장면을 재생한다.
8. `보험사 제출`과 `증거 채택`을 누른다.
9. Y 화면에서 `보상 지급 예정` 상태를 보여주며 종료한다.

## 9. 데모 안정성

- 발표 전에 2~3개의 영상을 실제 API로 시험한다.
- 가장 안정적으로 사고 후보와 타임스탬프가 나오는 약 20초 영상 하나를 기준 영상으로 정한다.
- TwelveLabs 실시간 호출 성공 시 `실시간 AI 분석 결과`로 표시한다.
- 네트워크나 공급자 장애 시에만 이전에 실제 분석해 저장한 결과를 사용할 수 있다.
- 저장 결과를 사용할 때는 화면에 반드시 `사전 분석 결과`라고 표시한다.
- 실제 분석 실패를 저장 결과로 조용히 대체하지 않는다.

## 10. MVP 완료 기준

- X의 사고 요청과 사고 묘사 사진이 저장된다.
- 장소·시간 매칭으로 Y 인앱 알림이 생성된다.
- iPhone 11에서 Y가 MP4를 선택하고 업로드할 수 있다.
- TwelveLabs가 실제 영상을 분석한다.
- AI가 반환한 사고 후보 타임스탬프가 화면에 표시된다.
- 타임스탬프를 누르면 영상이 해당 위치로 이동한다.
- 보험사 채택 및 보상 예정 Mock 상태까지 진행할 수 있다.
- 전체 happy path가 iPhone 11 세로 화면에서 가로 스크롤이나 막힌 동작 없이 완료된다.


## 11. 이번 MVP에서 제외

- X의 영상 업로드와 두 영상 간 직접 비교
- 실제 GPS 백그라운드 방문 기록 수집
- 실제 모바일 푸시 알림
- SD카드 전체 파일 자동 검색
- 장시간 블랙박스 영상 분석과 분할 업로드
- 별도 객체 추적 모델 학습
- 번호판 완전 자동 인식
- 경찰·보험사 시스템 API 연동
- 실제 PG·에스크로·환불·송금
- AI 단독 사고 확정 및 과실 비율 판단
